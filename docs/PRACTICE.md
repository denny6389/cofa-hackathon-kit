# 시험 전 코드 이해 연습

참가자가 시험 전에 직접 열어 사용하는 안내다. 시험 중 자동 로드용 문서가 아니다. 실제 시험 문제·코드·데이터·화면·개인정보는 사용하거나 수집하지 않는다. 목적은 모범답안 암기가 아니라 작은 구현을 읽고 자신의 말로 설명하는 연습이다.

## 가상 소규모 프로젝트

연습용으로만 다음 **지출 집계 CLI**를 별도 개인 연습 폴더에 준비한다. 아직 구현이 없다면 아래 가상 명세로 작은 구현을 만들고 실제 파일을 확보한 뒤 읽기 연습을 시작한다. 이 kit에는 연습 코드나 별도 제출 로그를 추가하지 않는다.

- 입력은 가상 CSV 파일이며 열은 `category`, `amount`다. 범주 앞뒤 공백은 제거하고 금액은 0 이상의 정수만 허용한다. 빈 범주·음수·정수가 아닌 금액·필수 열 누락은 오류로 알린다.
- 유효한 행의 금액을 범주별로 합친다. 합계 내림차순, 합계가 같으면 범주 이름 오름차순으로 출력한다. 데이터 행이 없으면 빈 결과를 출력한다.
- 입력 파일을 읽지 못하면 성공으로 표시하지 않고 오류를 알린다. 나머지 미정 사항은 구현 전에 정하고, 명세와 구현의 차이는 구분한다.

사람이 손으로 합산할 수 있는 작은 가상 입력과 독립 기대 결과부터 준비한다. 실제 코드 구조나 함수 이름은 구현을 확인해서 사용한다. 아래 예시 질문에 맞추려고 디렉토리를 억지로 나누지 않는다.

## 읽기 → 먼저 설명 → 근거 피드백 → 재설명

1. **코드 읽기:** 실행 진입점에서 입력 읽기·검증·집계·정렬·출력까지 따라간다. 핵심 파일·함수와 전달되는 값, 오류가 처리되는 위치를 찾는다. AI의 전체 해설을 먼저 읽기보다 한 기능이나 몇 개의 핵심 파일로 범위를 좁힌다.
2. **참가자 먼저 설명:** 코드를 근거로 자신의 말을 만든다. AI는 1~3개 질문을 제시하고 먼저 답할 기회를 준다. 막힌 부분은 모른다고 표시한다.
3. **실제 코드 근거 피드백:** AI가 실제 파일·함수·분기와 참가자의 설명을 비교해 맞는 부분, 빠진 조건, 잘못 짚은 내용을 알려준다. 없는 구현이나 실행하지 않은 검증을 가정하지 않는다.
4. **재설명:** 피드백 문장을 복사하지 않고 입력부터 결과까지 다시 설명한다. 입력 하나를 바꿨을 때 결과와 호출 흐름이 어떻게 달라지는지도 설명한다. 답변이 없으면 이해를 확인했다고 기록하지 않는다.

## 질문과 점검 관점

| 관점 | 스스로 설명할 질문 |
| --- | --- |
| 구조 | 각 디렉토리·파일의 책임과 실행 진입점은 어디인가? 이 분리가 필요한 이유는 무엇인가? |
| 로직 | CSV 한 행이 어떤 함수들을 지나 합계와 출력으로 바뀌는가? 검증 실패는 어느 경로로 처리되는가? |
| 설계 선택 | 집계·정렬에 어떤 알고리즘과 자료구조를 사용했는가? 다른 방식과 비교해 이 규모에서 선택한 이유는 무엇인가? |
| 규모·복잡도 | 행 수와 범주 수가 늘면 시간·메모리가 어느 단계에서 늘어나는가? 성능이 중요한 경우 실제 반복·정렬·저장 코드를 근거로 설명할 수 있는가? |
| 엣지케이스 | 빈 데이터, 금액 0, 합계 동률, 공백 범주, 잘못된 금액, 없는 파일 중 어떤 입력이 어느 분기를 통과하는가? |
| 검증 근거 | 기대값은 어디에서 얻었는가? 실행 명령·실제 출력과 맞는가? 실제 수정한 문제가 있다면 관찰→원인→수정→재검증을 설명할 수 있는가? |

모든 질문을 매번 묻지 않고 한 번에 1~3개를 고른다. 자잘한 수정마다 퀴즈나 새 승인 절차를 만들지 않는다.

## 검증하고 말하기

- 정상 입력과 관련 엣지케이스를 고르고, 기대 결과를 손계산·명세에서 구한다. 같은 구현 함수를 다시 호출해 기대값으로 삼지 않는다.
- 실제 명령과 출력이 있는 검증만 `PASS` 또는 `FAIL`로 기록한다. 실행하지 않았으면 `NOT_RUN`, 사람 확인이 남았으면 `HUMAN_CHECK`다. 이 연습의 결과를 실제 과제 검증 근거로 옮겨 쓰지 않는다.
- 구현이 명세를 어기면 실제 관찰을 먼저 설명하고, 수정 이유와 재검증을 확인한 뒤 달라진 동작을 재설명한다. 발견하지 않은 버그나 성공 결과를 만들지 않는다.

연습을 마칠 때는 구조·핵심 흐름·선택 이유·관련 예외·검증 근거를 자신의 말로 설명하고, 아직 불확실한 부분을 구분한다. 실제 서술형 단계에서는 해당 운영 규정에 따라 AI·붙여넣기 없이 직접 작성한다.
